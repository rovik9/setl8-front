## Implemented behavior

- `src/buy/rpc.ts`: only `https://api.devnet.solana.com` and `https://solana-devnet.api.onfinality.io/public`; no arbitrary environment URL, automatic retry, provider rotation or automatic resubmission. Any 403 blocks the client; 429/Retry-After stops both providers for the requested interval. Each operation is bounded to 32 reads, 12 seconds per request, 2.5 MB per response and 12 MB total. Cancellation also settles when a fetch implementation ignores its signal. Integer JSON number lexemes are retained exactly and monetary decisions require canonical u64 strings/bigints; safe numeric conversion is restricted to bounded request slots/sizes.
- `src/buy/preflight.ts`: compares fresh finalized public decision bytes from both operators twice with context floors. Checks pinned devnet genesis, upgradeable program links/authorities and full executable image hashes; strict SDK config/ruleset/registry/vault decoders; current pauses/tier size and price; wallet owner/counter/eligibility and vacant expected account/trader-state PDAs; six-decimal classic test-USDC mint, existing source/destination authorities and usable token state; exact integer funds, SDK message fee and account rent; selected blockhash validity and heights. Different providers’ latest hashes need not match. The original exact blockhash is checked again, not replaced. Review lifetime is 30 seconds, with checks across revalidation, persistence and the prompt boundary. No simulation is performed in this review stage.
- `src/buy/wallets.ts`: explicitly discovers supported/unsupported Wallet Standard capabilities and devnet accounts; requires legacy `solana:signTransaction`, never invokes `signAndSendTransaction`; connection/network/account events invalidate captured signers and reviews. Multiple accounts require explicit selection. No wallet is connected automatically.
- `src/buy/purchaseFlow.ts`, `signed.ts`, `recovery.ts`: the production port refuses approval and send. The injected offline test port exercises the intended sequence: current review/context checks → cross-tab Web Lock → exact public attempt durably retained/read back before a wallet prompt → returned message equality and required Ed25519 signature verification → exact signature retained before one mocked app send → read-only reconciliation. No private keys, signed packets, session tokens or cookies are stored. Journal corruption/storage failures block approval. Wallet changes, rejection, missing status, elapsed review/blockhash and lost send responses never clear the attempt or enable repayment. There is deliberately no delete/unlock/new-payment action, including after verified origin.
- `src/buy/receipt.ts`: bounded two-operator supplied-metadata correlation of exact message/signature, successful finalized transaction, the approved SDK plan, complete bounded Opened self-CPI trace/authority/parent, exact SPL transfer/balance identities and amounts, fresh reviewed executable images, expected account owner/size, wallet counter, trader state and exact signature in bounded account-origin history. Confirmed observations remain pending. Missing, contradictory or truncated evidence remains uncertain. Matching actual debit yields verified **origin only**; an observed finalized origin with different reviewed debit is flagged separately. This is not cryptographic execution/finality proof and does not establish full journal coverage, terminal readiness or a debit-cap guarantee. Strict cross-provider metadata matching can conservatively remain uncertain when reports differ.
