# Owner devnet checkout sequence — default OFF

The sign-only/single-send implementation and unsigned/signed simulation paths now exist and are validated offline. This file does not activate them. Real approval/sending requires a separately reviewed source change to the OFF release record; a URL, environment variable, localStorage value or Origin acceptance boolean cannot activate the public route.

1. **Approve one concrete owner scope.** Give Origin the owner’s public devnet wallet address, one purchase scope, authorization reference and short activation window. Review the local code/build with `DIRECT_GATE.sign/send` and the wallet-scoped/time-bounded `OWNER_RELEASE` record before explicitly authorizing activation. The owner retains their wallet/key; no private wallet access is needed by the implementation agent.
2. **Resolve read access and prepare existing accounts.** Both fixed public endpoints must permit the fresh check. The first finite A1 read hit OnFinality429. Later separately authorized public-read windows have separate evidence; access is not assumed across windows. The corrected measured bound is37 RPC calls through one send (18 initial +8 pre-wallet +8 post-wallet +2 simulations +1 send), or35 with an existing profile. A separately requested successful finalized-origin reconciliation is up to8 more. This replaces the rejected117-call plan; it is not an automatic allowance and is separate from the earlier ten-read A1 budget. No automatic retries/failover occur. Owner wallet must support Wallet Standard legacy `signTransaction` on devnet and already hold sufficient devnet SOL and classic test-USDC at the pinned mint; source, vault pool, platform and fee token accounts must exist and pass identity/state checks. This app does not create, mint or fund them.
3. **Connect and review fresh terms.** On normal5173 `/buy`, owner connects/selects the explicitly authorized public wallet, chooses a tier, clicks Review, and inspects current size, price/fee/total, exact network fee/rent, expected account and message details. The original review expires30s after completed creation, capped by oldest decision evidence+60s, and must remain valid. A future activated UI requires the checkbox bound to this exact wallet/epoch/account/message/fingerprint/time/total, explicitly acknowledging devnet test tokens and the absence of an instruction-level signed debit cap/expiry. A new review requires a new acknowledgement.
4. **Owner approves one exact message.** The app first revalidates the original message’s dependencies before the wallet, then durably retains the public attempt, then simulates the exact unsigned packet with sigVerify=false without replacing its blockhash. Owner reviews and signs in their external wallet. The app copies and verifies the exact returned bytes/Ed25519 signature, durably retains the signature, revalidates original dependencies after the wallet, then simulates that exact signed packet with sigVerify=true. Local expiry/cancellation/context/retained-signature checks precede one app send with maxRetries=0 and server preflight enabled. There is no further full revalidation after either simulation. Signed simulation is required: unsupported/error/truncated/stale evidence blocks sending, with no fallback.
5. **Reconcile, never repay on uncertainty.** A send response is not execution/finality. Use Check again/read-only and Explorer against the retained exact signature/account. Missing status, expiry, rejection, simulation failure, lost response, wallet change or incomplete evidence never enable a replacement purchase. The public record stays retained even after corroborated origin; there is no unlock/delete/new-payment shortcut. Proof updates/payout actions are separate owner work.

Simulation is advisory and does not sign or enforce a maximum debit. The contract’s current configuration can change between observation and execution. The signed blockhash bounds message validity; it is not an explicit open-account expiry/debit cap. No real wallet prompt, transaction, funding or extra synthetic fixture was used to prepare this code.
